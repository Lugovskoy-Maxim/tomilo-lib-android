# Аудит Android-приложения TOMILO LIB

Дата аудита: 2026-09-23
Область: исходники `app/`, сборочная конфигурация, манифест, существующие тесты и дизайн-спецификация. Аудит и доработки выполняются поэтапно. Сборка Rustore Debug проверена; сценарии на устройстве/API и визуальная проверка на физических размерах пока не выполнялись. Непроверенные пункты остаются отмечены как риски, а не подтверждённые воспроизводимые дефекты.

## P0 — исправить до следующего релиза

- [x] **Перенести секреты сессии из обычного Preferences DataStore в защищённое хранилище.** `AuthStore` хранит access/refresh JWT как обычные строки; `allowBackup=true`, а XML-правила резервного копирования оставлены шаблонными и не исключают DataStore. Определить политику восстановления для токенов и профиля, шифровать чувствительные значения Android Keystore-backed ключом и исключить их из облачного backup/device transfer. Файлы: `app/src/main/java/ru/tomilo/lib/mobile/data/local/AuthStore.kt`, `app/src/main/AndroidManifest.xml`, `app/src/main/res/xml/data_extraction_rules.xml`, `app/src/main/res/xml/backup_rules.xml`.
- [x] **Убрать потерю пользовательских офлайн-данных при обновлении схемы Room.** `OfflineDatabase` использует `.fallbackToDestructiveMigration()` и `exportSchema = false`; несовместимая миграция тихо удалит список скачанных глав/метаданные. Добавить экспорт схем, versioned migrations и проверку восстановления файлово-БД состояния. Файл: `app/src/main/java/ru/tomilo/lib/mobile/data/local/OfflineDatabase.kt`.
- [x] **Частично согласовать target SDK 36 с требованиями Android 15/16.** Проверить edge-to-edge, системные панели и foreground data-sync service limits/timeout на API 35–36, включая действие пользователя после превышения лимита. В манифесте объявлен `FOREGROUND_SERVICE_DATA_SYNC`, сервис бессрочно выполняет очередь; проверить остановку и возобновление, чтобы ОС не завершала сервис посреди главы. Файлы: `app/build.gradle.kts`, `app/src/main/AndroidManifest.xml`, `app/src/main/java/ru/tomilo/lib/mobile/data/download/DownloadForegroundService.kt`, `app/src/main/java/ru/tomilo/lib/mobile/data/download/DownloadManager.kt`.

## P1 — важные исправления и надёжность

- [ ] **Сделать обновление access token отменяемым и ограниченным по времени.** `Authenticator` выполняет `runBlocking` при записи токенов через callback `AppContainer`; синхронная запись DataStore может надолго удерживать сетевой поток/цепочку обновления. Вынести refresh в единый безопасный механизм с дедлайном, защитой от параллельных refresh и явным logout при недействительном refresh token. Файлы: `app/src/main/java/ru/tomilo/lib/mobile/AppContainer.kt`, `app/src/main/java/ru/tomilo/lib/mobile/data/api/NetworkModule.kt`.
- [ ] **Проверить защиту от межаккаунтного показа приватных ответов из HTTP cache.** Кеш задаёт политику только по наличию `Authorization`, но при logout/login cache не очищается, а новый публичный GET может совпасть с ранее закешированным URL. Проверить порядок interceptor-ов и сценарии с `Vary: Authorization`; надёжнее отключить/очищать API-кеш при смене аккаунта и покрыть сценарии интеграционными тестами. Это риск, требующий воспроизведения, а не подтверждённая утечка. Файлы: `NetworkModule.kt`, `AuthRepository.kt`, `TomiloApp.kt`.
- [x] **Перенести запрос разрешения уведомлений из первого кадра приложения в объяснённый контекст.** Сейчас `POST_NOTIFICATIONS` запрашивается в `MainActivity.onCreate()` сразу после старта, до объяснения ценности и пользовательского намерения. Запрашивать при включении уведомлений/после показа контекста; корректно обрабатывать отказ и повторный вход в настройки. Файл: `app/src/main/java/ru/tomilo/lib/mobile/MainActivity.kt`.
- [x] **Сделать поиск устойчивым к устаревшим ответам.** В `SearchScreen` debounce-поиск запускается в `LaunchedEffect`, но репозиторный вызов использует `Result` и может перехватывать отмену coroutine; быстрые запросы могут завершаться не по порядку и перезаписывать актуальную выдачу. Использовать cancellable API/проверку актуального query перед публикацией результата и не записывать историю на каждом успешном повторе. Файлы: `SearchScreen.kt`, `CatalogRepository.kt`.
- [ ] **Уточнить логику сравнения свежести в polling уведомлений.** В `NotificationsPollWorker` при непустом ответе `KEY_LAST_SEEN_ID` обновляется до фактической доставки всех уведомлений; если `showUpdate()` вернул false (разрешение запрещено/сбой), события могут быть помечены как просмотренные и повторно не выданы. Проверить, что `knownIds`/last-seen согласованы для отказа разрешения и лимитов уведомлений. Файл: `app/src/main/java/ru/tomilo/lib/mobile/push/NotificationsPollWorker.kt`.
- [x] **Синхронизировать версию в документации сборки.** `BUILD.md` ранее указывал 1.3.4 / versionCode 40; значения синхронизированы с 1.3.5 / 41. Единый источник версии в release workflow отдельно не проверен. Файлы: `BUILD.md`, `app/build.gradle.kts`, `.github/RELEASE.md`, `.github/workflows/release.yml`.
- [ ] **Упорядочить версионный каталог зависимостей.** Корневой `gradle/libs.versions.toml` не является источником версий для приложения: там Compose BOM 2024.09.00, Room 2.7.0 и Retrofit 2.12.0, а `app/build.gradle.kts` напрямую задаёт другие версии (Compose BOM 2024.12.01, Room 2.6.1, Retrofit 2.11.0). Перевести зависимости на каталог либо удалить устаревшие дубли после проверки сборочных скриптов, затем зафиксировать процесс обновления и совместимости AGP/Kotlin/KSP.

## P2 — техдолг и качество сопровождения

- [ ] **Добавить тесты критических сценариев.** Сейчас есть unit-тесты для отдельных форматтеров, DTO, прогресса загрузки, уведомлений и нескольких UI-компонентов, но нет видимого `androidTest` набора. Приоритет: refresh токена и logout, cache isolation, миграции Room, повтор/отмена фоновой загрузки, поиск с out-of-order ответами, permission denial, deep links из уведомлений и платежные состояния. Существующее покрытие — 12 файлов в `app/src/test`.
- [ ] **Заменить широко применённые `!!` на безопасные модели состояния.** Поиск нашёл force unwrap в профиле, Premium, админ-экранах и фильтрах каталога. Часть мест может быть защищена UI-условием, но инвариант не выражен типами; убрать падения при обновлении состояния/быстром переключении аккаунта и локализовать обработку optional данных.
- [ ] **Разделить огромные UI-модули и состояние экранов.** Крупные `HomeScreen.kt`, `CatalogScreen.kt`, `TitleScreen.kt`, `ReaderScreen.kt`, `ProfileScreen.kt`, `AdminScreens.kt` содержат сложную композицию и локальное состояние. Выделить state holder/ViewModel, компоненты и use case-ы по ответственности; сначала — reader, catalog и платежные потоки.
- [ ] **Стандартизировать сетевые ошибки и отмену.** Репозитории часто оборачивают вызовы в `runCatching`, которое также поглощает `CancellationException`; проверить все repository/Compose loaders и повторно выбрасывать отмену. Привести API-ошибки к типизированной модели для различения offline, auth, rate limit и server error.
- [ ] **Проверить историю чтения и незавершённые фоновые операции.** `DownloadManager` хранит очередь в памяти процесса, хотя сервис использует `START_STICKY`; после уничтожения процесса очередь не может восстановиться полностью. Сравнить обещание «скачивание продолжится в фоне» с поведением при process death и перевести durable work на WorkManager/персистентную очередь либо описать ожидаемое ограничение.
- [ ] **Сократить повторные сетевые запросы и разделить ответственность polling.** Worker одновременно опрашивает уведомления, новые главы в закладках и разговоры; проверить бюджет запросов, расписание, backoff и реакцию на серверные лимиты для больших аккаунтов.
- [ ] **Зафиксировать правила логирования и диагностических данных.** BASIC HTTP logging включён в debug — проверить, что URL/query не содержат секретов; ошибки SDK рекламы логируются. Утвердить маскирование идентификаторов и диагностический сценарий для production без утечки токенов/платёжных данных.
- [ ] **Добавить статический анализ и проверку доступности в CI.** Подключить lint/detekt или эквивалент для Kotlin, Android lint на release-вариантах, проверку manifest/permissions и базовые accessibility checks Compose. Исправить документированные сборочные расхождения прежде, чем делать проверки обязательными.

## P2 — визуальное оформление и UX (в русле `DESIGN.md`)

- [x] **Подключить заявленный шрифт Exo 2.** `DESIGN.md` фиксирует Exo 2, но `TomiloTypography` задаёт только размеры и веса, не `FontFamily`; сейчас используется системный шрифт. Добавить оптимизированные локальные font resources с нужными начертаниями или обновить спецификацию, затем проверить кириллицу, динамический размер шрифта и ширину длинных названий. Файлы: `DESIGN.md`, `app/src/main/java/ru/tomilo/lib/mobile/ui/theme/Type.kt`, `app/src/main/res/`.
- [x] **Свести системную тему Android к Compose-палитре.** XML тема задаёт сине-фиолетовый `colorPrimary` `#FF6B8CFF` и панели `#FF1A1D24`, тогда как Compose использует графит/коралл; это может давать цветовой скачок на splash, системных диалогах и переходах. Привести системные атрибуты/иконки status bar к палитре, проверить светлую/тёмную тему и edge-to-edge на реальных устройствах. Файл: `app/src/main/res/values/themes.xml`.
- [ ] **Сделать визуальную систему адаптивной к реальной плотности и размеру окна.** Макетные цифры в `DESIGN.md` указаны в px, а интерфейс Compose использует dp/sp. Уточнить, что спецификация — экспортный размер, перевести токены в dp/sp и проверить компактные телефоны, большие экраны, split-screen, landscape и системный font scale 1.3–2.0.
- [ ] **Унифицировать размеры и интерактивные зоны.** Сверить минимальные зоны нажатия (48 dp и выше для ключевых целей), радиусы, сетку отступов, высоты top/bottom bars, контраст вторичного текста и толщину иконок. Подровнять экраны, где локальные размеры/стили обходят `MaterialTheme` и общие компоненты.
- [ ] **Довести состояния экранов до единого стандарта.** Для каталога, профиля, уведомлений, игр, комментариев и Premium проверить четыре состояния: загрузка, ошибка с повтором, пустой результат с полезным действием, offline/disabled. Сейчас часть экранов показывает простой EmptyState/ErrorBox; добавить предметные иллюстрации и понятные CTA в соответствии с `UX_GRAPHICS_IDEAS.md`.
- [ ] **Добавить фирменные графические состояния вместо универсальных заглушек.** Подготовить лёгкие векторные иллюстрации: пустая полка, история, офлайн, поиск без результатов, уведомления, ошибка; детерминированные текстурные fallback-обложки для отсутствующих постеров; унифицированные быстрые действия. Важные смыслы дублировать текстом, задавать корректные `contentDescription`.
- [ ] **Показать прогресс чтения непосредственно на обложках.** В карточках «Продолжить» и библиотеки добавить тонкую полосу/маркер последней главы, сохранив название и обложку основным фокусом; предусмотреть нулевой/неизвестный прогресс и доступность без зависимости от цвета.
- [ ] **Проверить доступность во всех экранах.** Увеличенные системные шрифты, TalkBack-порядок, описания действий и обложек, семантика прогрессов/счётчиков, контраст, нецветовые маркеры статусов, клавиатура и крупные touch targets. `EmptyState` передаёт декоративной иконке null description — проверить, что рядом всегда есть достаточный текст.

## P3 — анимации и эффекты

- [x] **Уважать системное отключение анимаций в общих loading/empty/skeleton-компонентах.** Общие `rememberInfiniteTransition` в shimmer, `LoadingBox` и `EmptyState` работают бесконечно без проверки системной длительности анимаций. При отключённой анимации показывать статичный skeleton/индикатор; не запускать декоративное движение в невидимых composable. Файлы: `ui/components/Skeletons.kt`, `ui/components/UiKit.kt`.
- [ ] **Сократить постоянную стоимость shimmer и декоративных циклов.** Пересмотреть бесконечный shimmer на всех skeleton-элементах и вращающийся halo загрузки; использовать общую анимацию на видимом контейнере, анимировать только alpha/translation, выключать при offscreen и на слабых устройствах. Сохранить короткие переходы и читабельность.
- [ ] **Завершить состояния обратной связи интеракций.** Единообразно добавить pressed/selected/loading переходы для карточек, фильтров, действий закладки/скачивания, кнопок наград, переключения нижней навигации и появления snackbar. Использовать короткие spring/fade/scale эффекты, избегать анимации layout-размеров для длинных списков.
- [ ] **Проверить анимацию переходов между экранами и восстановления состояния.** Добавить согласованные enter/exit переходы там, где они помогают понять навигацию; не анимировать reader-переходы так, чтобы задерживалось чтение или пагинация. Сохранить scroll position и состояние фильтра после возврата.
- [ ] **Сделать эффекты игрового раздела информативными и сдержанными.** Колесо, выдача награды, прогресс заданий и карточные игры должны иметь понятное начало/завершение, доступный текстовый результат, ограниченную длительность и корректный результат при отмене/сворачивании приложения; уважать Reduce motion.
- [ ] **Задать критерии производительности motion.** На реальных бюджетных устройствах измерить jank/кадры для ленты с изображениями, shimmer-сетки каталога, скролла читалки и вращения колеса; устранять лишние recomposition и дорогие blur/shadow только по измерениям.
