# Аудит Android-приложения TOMILO LIB

Дата аудита: 2026-09-23
Область: исходники `app/`, сборочная конфигурация, манифест, существующие тесты и дизайн-спецификация. Аудит и доработки выполняются поэтапно. `:app:assembleRustoreDebug` проходит; приложение установлено на компактный AVD Compact Phone API 37 (экран 720×1600, 320 dpi, SwiftShader; системный образ фактически выделяет гостю 4 ГБ RAM), проверен экран запуска приложения, фатальных ошибок в просмотренном logcat не было. Главная загрузилась в сетевом error-state, поэтому живые игровые данные не проверены; компактные физические устройства и runtime-сценарии API остаются непроверенными; AVD использует единственный установленный образ Android 37.1 Play Store, так как SDK manager/другие system image локально отсутствовали. Непроверенные пункты остаются рисками, а не подтверждёнными воспроизводимыми дефектами.

Файлы: `app/src/main/java/ru/tomilo/lib/mobile/data/local/AuthStore.kt`, `app/src/main/AndroidManifest.xml`, `app/src/main/res/xml/data_extraction_rules.xml`, `app/src/main/res/xml/backup_rules.xml`.

Добавить экспорт схем, versioned migrations и проверку восстановления файлово-БД состояния. Файл: `app/src/main/java/ru/tomilo/lib/mobile/data/local/OfflineDatabase.kt`.

## P1 — важные исправления и надёжность

- [x] **Защитить refresh от блокировки UI и гонок с logout/login.** Authenticator синхронно сохраняет ротацию только на `Dispatchers.IO`; пара access/refresh сравнивается в памяти и атомарно в DataStore с исходной сессией. Подтверждённый HTTP 401 от refresh удаляет сессию только если те же токены всё ещё активны; сетевые ошибки не разлогинивают пользователя. Runtime проверки параллельных 401/logout остаются частью незакрытого набора интеграционных тестов. Файлы: `AppContainer.kt`, `NetworkModule.kt`, `AuthStore.kt`, `AuthRepository.kt`.
- [x] **Исключить межаккаунтное чтение API cache.** Любой API-запрос с `Authorization` теперь уходит с request `Cache-Control: no-store` (запрещает cache hit и запись), для авторизованных ответов также задаётся `no-store`. Это закрывает сценарий, когда анонимный ответ по тому же URL переживает вход. Интеграционное воспроизведение смены аккаунта ещё не добавлено. Файл: `app/src/main/java/ru/tomilo/lib/mobile/data/api/NetworkModule.kt`.
- [x] **Перенести запрос разрешения уведомлений из первого кадра приложения в объяснённый контекст.** Сейчас `POST_NOTIFICATIONS` запрашивается в `MainActivity.onCreate()` сразу после старта, до объяснения ценности и пользовательского намерения. Запрашивать при включении уведомлений/после показа контекста; корректно обрабатывать отказ и повторный вход в настройки. Файл: `app/src/main/java/ru/tomilo/lib/mobile/MainActivity.kt`.
- [x] **Сделать поиск устойчивым к устаревшим ответам.** В `SearchScreen` debounce-поиск запускается в `LaunchedEffect`, но репозиторный вызов использует `Result` и может перехватывать отмену coroutine; быстрые запросы могут завершаться не по порядку и перезаписывать актуальную выдачу. Использовать cancellable API/проверку актуального query перед публикацией результата и не записывать историю на каждом успешном повторе. Файлы: `SearchScreen.kt`, `CatalogRepository.kt`.
- [x] **Не терять уведомления, если Android отклонил доставку.** Проверено: в непустой серверной ленте ID попадает в `knownIds` только если `showUpdate()` вернул `true`; `KEY_LAST_SEEN_ID` не используется как фильтр новых событий. Исправлено продвижение baseline для сводного unread-уведомления: счётчик сохраняется только после фактической доставки сводки/специализированного уведомления либо после уменьшения unread. Повторная доставка после отказа разрешения остаётся непроверенной интеграционно. Файл: `app/src/main/java/ru/tomilo/lib/mobile/push/NotificationsPollWorker.kt`.
- [x] **Синхронизировать версию в документации сборки.** `BUILD.md` ранее указывал 1.3.4 / versionCode 40; значения синхронизированы с 1.3.5 / 41. Единый источник версии в release workflow отдельно не проверен. Файлы: `BUILD.md`, `app/build.gradle.kts`, `.github/RELEASE.md`, `.github/workflows/release.yml`.
- [ ] **Упорядочить версионный каталог зависимостей.** Корневой `gradle/libs.versions.toml` не является источником версий для приложения: там Compose BOM 2024.09.00, Room 2.7.0 и Retrofit 2.12.0, а `app/build.gradle.kts` напрямую задаёт другие версии (Compose BOM 2024.12.01, Room 2.6.1, Retrofit 2.11.0). Перевести зависимости на каталог либо удалить устаревшие дубли после проверки сборочных скриптов, затем зафиксировать процесс обновления и совместимости AGP/Kotlin/KSP.

## P2 — техдолг и качество сопровождения

- [ ] **Добавить тесты критических сценариев.** Сейчас есть unit-тесты для отдельных форматтеров, DTO, прогресса загрузки, уведомлений и нескольких UI-компонентов, но нет видимого `androidTest` набора. Приоритет: refresh токена и logout, cache isolation, миграции Room, повтор/отмена фоновой загрузки, поиск с out-of-order ответами, permission denial, deep links из уведомлений и платежные состояния. Существующее покрытие — 12 файлов в `app/src/test`.
- [x] **Убрать force unwrap из Android Kotlin-исходников.** Удалены оставшиеся `!!` в title/wheel/profile state, форме входа, ошибках чатов/уведомлений, выборе фильтра и admin action. В офлайн-загрузке Room-запись, исчезнувшая после проверки файлов, больше не приводит к crash; при отсутствии metadata загрузка продолжает сетевой путь. Поиск `rg '!!' app/src/main/java/ru/tomilo/lib/mobile --glob '*.kt'` пуст. Переключение аккаунта и гонки Room требуют отдельной интеграционной проверки.
- [ ] **Разделить огромные UI-модули и состояние экранов.** Крупные `HomeScreen.kt`, `CatalogScreen.kt`, `TitleScreen.kt`, `ReaderScreen.kt`, `ProfileScreen.kt`, `AdminScreens.kt` содержат сложную композицию и локальное состояние. Выделить state holder/ViewModel, компоненты и use case-ы по ответственности; сначала — reader, catalog и платежные потоки.
- [x] **Не преобразовывать отмену сетевого запроса в ошибку экрана.** Общий `runCatchingCancellable` теперь применяется к suspend-вызовам в Auth, Catalog, History, Payments, Social, Admin, Games и Offline репозиториях; вложенные fallback-запросы также повторно выбрасывают `CancellationException`. Оставшиеся обычные `runCatching` используются только для синхронного декодирования/парсинга. Типизированное различение offline/auth/rate-limit/server ошибок остаётся незакрытым техдолгом.
- [ ] **Довести восстановление фоновых загрузок до надёжного durable-work процесса.** Добавлен персистентный checkpoint запроса, восстановление очереди при `START_STICKY` и возобновление после Android 15 data-sync timeout при следующем открытии приложения. Выполненные главы безопасно пропускаются, незавершённая глава продолжает загрузку по уже сохранённым страницам. Осталось проверить process death/API 35–36 на устройстве и решить возобновление без возвращения пользователя (например, через WorkManager после истечения FGS-бюджета).
- [ ] **Сократить повторные сетевые запросы и разделить ответственность polling.** Worker одновременно опрашивает уведомления, новые главы в закладках и разговоры; проверить бюджет запросов, расписание, backoff и реакцию на серверные лимиты для больших аккаунтов.
- [ ] **Зафиксировать правила логирования и диагностических данных.** BASIC HTTP logging включён в debug — проверить, что URL/query не содержат секретов; ошибки SDK рекламы логируются. Утвердить маскирование идентификаторов и диагностический сценарий для production без утечки токенов/платёжных данных.
- [ ] **Добавить статический анализ и проверку доступности в CI.** Подключить lint/detekt или эквивалент для Kotlin, Android lint на release-вариантах, проверку manifest/permissions и базовые accessibility checks Compose. Исправить документированные сборочные расхождения прежде, чем делать проверки обязательными.

## P3 — анимации и эффекты

- [x] **Уважать системное отключение анимаций в общих loading/empty/skeleton-компонентах.** Общие `rememberInfiniteTransition` в shimmer, `LoadingBox` и `EmptyState` работают бесконечно без проверки системной длительности анимаций. При отключённой анимации показывать статичный skeleton/индикатор; не запускать декоративное движение в невидимых composable. Файлы: `ui/components/Skeletons.kt`, `ui/components/UiKit.kt`.

Осталось измерить нагрузку на слабом устройстве и проверить offscreen-поведение, вращающийся halo и остальные циклы.
- [ ] **Завершить состояния обратной связи интеракций.** Единообразно добавить pressed/selected/loading переходы для карточек, фильтров, действий закладки/скачивания, кнопок наград, переключения нижней навигации и появления snackbar.
