# Аудит Android-приложения TOMILO LIB

Дата аудита: 2026-09-24
Область: исходники `app/`, сборочная конфигурация, манифест, существующие тесты и дизайн-спецификация. Аудит и доработки выполняются поэтапно. `:app:assembleRustoreDebug` проходит; приложение установлено и запущено на компактном AVD Compact Phone API 37 (720×1600, 320 dpi, SwiftShader; системный образ фактически выделяет гостю 4 ГБ RAM). После onboarding открылся главный экран; фатальных ошибок в просмотренном logcat не было. Публичные альбом и магазин карточек проверены без авторизации; покупка, обмены и кузница требуют авторизованной сессии, которой на AVD нет, поэтому формы и живые операции остаются непроверенными. Компактные физические устройства и runtime-сценарии API также не проверены; AVD использует единственный установленный Android 37.1 Play Store образ. Непроверенные пункты остаются рисками, а не подтверждёнными воспроизводимыми дефектами.

## P1 — важные исправления и надёжность

- [x] **Защитить refresh от блокировки UI и гонок с logout/login.** Authenticator синхронно сохраняет ротацию только на `Dispatchers.IO`; пара access/refresh сравнивается в памяти и атомарно в DataStore с исходной сессией. Подтверждённый HTTP 401 от refresh удаляет сессию только если те же токены всё ещё активны; сетевые ошибки не разлогинивают пользователя. Runtime проверки параллельных 401/logout остаются частью незакрытого набора интеграционных тестов. Файлы: `AppContainer.kt`, `NetworkModule.kt`, `AuthStore.kt`, `AuthRepository.kt`.
- [x] **Исключить межаккаунтное чтение API cache.** Любой API-запрос с `Authorization` теперь уходит с request `Cache-Control: no-store` (запрещает cache hit и запись), для авторизованных ответов также задаётся `no-store`. Это закрывает сценарий, когда анонимный ответ по тому же URL переживает вход. Интеграционное воспроизведение смены аккаунта ещё не добавлено. Файл: `app/src/main/java/ru/tomilo/lib/mobile/data/api/NetworkModule.kt`.
- [x] **Перенести запрос разрешения уведомлений из первого кадра приложения в объяснённый контекст.** Сейчас `POST_NOTIFICATIONS` запрашивается в `MainActivity.onCreate()` сразу после старта, до объяснения ценности и пользовательского намерения. Запрашивать при включении уведомлений/после показа контекста; корректно обрабатывать отказ и повторный вход в настройки. Файл: `app/src/main/java/ru/tomilo/lib/mobile/MainActivity.kt`.
- [x] **Сделать поиск устойчивым к устаревшим ответам.** В `SearchScreen` debounce-поиск запускается в `LaunchedEffect`, но репозиторный вызов использует `Result` и может перехватывать отмену coroutine; быстрые запросы могут завершаться не по порядку и перезаписывать актуальную выдачу. Использовать cancellable API/проверку актуального query перед публикацией результата и не записывать историю на каждом успешном повторе. Файлы: `SearchScreen.kt`, `CatalogRepository.kt`.

Ошибка endpoint-а счётчика теперь сохраняется как `Result`, не сбрасывает baseline в ноль и приводит к ограниченному retry worker-а; профиль по-прежнему показывает 0 при ошибке загрузки. ## P2 — техдолг и качество сопровождения

- [ ] **Добавить тесты критических сценариев.** Существуют unit-тесты отдельных форматтеров, DTO, прогресса загрузки, уведомлений и нескольких UI-компонентов; `androidTest` набора нет. Добавлен чистый `CardEconomy` и четыре unit-теста на нормализацию серверного/legacy ранга, fallback редкости, progression кузницы и формулу продажи карточек. Для общей обёртки репозитория проверены success, обычная ошибка и проброс `CancellationException`, чтобы отмена coroutine не становилась UI-ошибкой. JSON-checkpoint очереди офлайн-загрузки вынесен в чистый codec и проверен round-trip, неизвестными полями будущего формата и некорректной/неполной записью. Для повторов загрузки страниц читалки добавлена pure-политика: cache-bust nonce теперь не обрезает ручной повтор после первого запроса; автоматический retry ограничен отдельными циклами, покрыты тестами. Для «Рецепта бодрости» правила поля 8×8 вынесены в pure helper с тестами валидных/невалидных ходов, отсутствия бесплатной стартовой линии и обновления собранных клеток. Ещё не покрыты refresh/logout и cache isolation, Room migrations, повтор/отмена пакетной загрузки, out-of-order поиск, permission denial, большинство deep links и платежные состояния; восстановление процесса по-прежнему требует instrumentation-теста.
- [x] **Сохранить карточный раздел при смене конфигурации и не терять раннюю ссылку уведомления.** Страница хаба и активная вкладка карточек используют saveable state: на Compact Phone API 37 после смены font scale 1.0 → 1.3 → 1.0 осталась открыта вкладка «Магазин». При холодном старте уведомительная ссылка раньше могла вызвать `navigate()` до установки графа Navigation; обработчик теперь ждёт первый back stack entry, переход на `games` проверен на эмуляторе без падения. Другие маршруты уведомлений и восстановление процесса ещё проверить.
- [x] **Убрать force unwrap из Android Kotlin-исходников.** Удалены оставшиеся `!!` в title/wheel/profile state, форме входа, ошибках чатов/уведомлений, выборе фильтра и admin action. В офлайн-загрузке Room-запись, исчезнувшая после проверки файлов, больше не приводит к crash; при отсутствии metadata загрузка продолжает сетевой путь. Поиск `rg '!!' app/src/main/java/ru/tomilo/lib/mobile --glob '*.kt'` пуст. Переключение аккаунта и гонки Room требуют отдельной интеграционной проверки.
- [ ] **Разделить огромные UI-модули и состояние экранов.** Крупные `HomeScreen.kt`, `CatalogScreen.kt`, `TitleScreen.kt`, `ReaderScreen.kt`, `ProfileScreen.kt`, `AdminScreens.kt` содержат сложную композицию и локальное состояние. Выделить state holder/ViewModel, компоненты и use case-ы по ответственности; сначала — reader, catalog и платежные потоки.
- [x] **Не преобразовывать отмену сетевого запроса в ошибку экрана.** Общий `runCatchingCancellable` теперь применяется к suspend-вызовам в Auth, Catalog, History, Payments, Social, Admin, Games и Offline репозиториях; вложенные fallback-запросы также повторно выбрасывают `CancellationException`. Для общей UI-ошибки покрыты тестами успех, обычная ошибка и проброс отмены. Оставшиеся обычные `runCatching` используются только для синхронного декодирования/парсинга. Типизированное различение offline/auth/rate-limit/server ошибок вне общей UI-обёртки остаётся техдолгом.
- [ ] **Довести восстановление фоновых загрузок до надёжного durable-work процесса.** Персистентный checkpoint запроса восстанавливается при `START_STICKY`; после Android 15 data-sync timeout очередь теперь автоматически передаётся в unique WorkManager-задачу с сетевым ограничением и exponential backoff — повторное открытие приложения не требуется. WorkManager обновляет состояние загрузки/уведомление, использует тот же checkpoint, а отмена из уведомления отменяет активный worker и очищает очередь. Сервис и worker сериализованы mutex-ом, чтобы не обрабатывать одну очередь параллельно. Выполненные главы безопасно пропускаются, незавершённая глава продолжает загрузку по сохранённым страницам; после частичного сбоя checkpoint теперь содержит только главы не в статусе `Completed`, а успешная явная очистка удаляет его. Worker теперь возвращает retry, если после прохода остались failed/cancelled главы; checkpoint содержит только незавершённые, для критерия добавлены unit-тесты. Осталось проверить реальный process death и timeout на API 35–36, а также длительную задачу, прерванную лимитом WorkManager.
- [ ] **Сократить повторные сетевые запросы и разделить ответственность polling.** Worker одновременно опрашивает уведомления, новые главы в закладках и разговоры; проверить бюджет запросов, расписание, backoff и реакцию на серверные лимиты для больших аккаунтов. API GET retry теперь соблюдает `Retry-After` в секундах и HTTP-date для 429/503/прочих retryable ответов; если сервер просит ждать больше 15 секунд, interceptor возвращает ответ без раннего повтора. При потере connectivity IOException больше не тратит оставшиеся попытки с задержкой. Загрузка прогресса тайтлов в истории/закладках теперь выполняется параллельно с лимитом 4 запроса вместо последовательного ожидания каждого ответа; ошибки conversations, support inbox и bookmarks больше не маскируются под пустой результат: после сохранения доставленных событий worker ограниченно повторяет частично неудачный опрос с WorkManager backoff. Экран чатов теперь запускает 12-секундный polling только при `Lifecycle.STARTED`, а при возврате загружает актуальные данные; ошибки списка/inbox нормализуются. Общий бюджет polling worker всё ещё требует отдельного профилирования.
- [ ] **Зафиксировать правила логирования и диагностических данных.** BASIC HTTP logging включён только в debug; URL query в debug-логгере маскируют `token`, `key`, `email`, `phone`, `search/q`, `session`, `code` и похожие параметры, а auth/cookie/API-key headers задекларированы как redacted. Ошибки SDK рекламы логируются. Осталось утвердить полный список чувствительных полей и диагностический сценарий для production без утечки токенов/платёжных данных.
- [ ] **Добавить статический анализ и проверку доступности в CI.** Android lint Rustore debug-варианта и lint обеих release-конфигураций (`rustore`, `play`) выполняются в CI; локально `:app:lintRustoreDebug`, `:app:lintRustoreRelease` и `:app:lintPlayRelease` прошли без ошибок. Debug-отчёт от 2026-09-24 содержит 99 warning и 4 hint (включая устаревающие зависимости, иконки и стиль API). Исправлена Compose-подсказка `AutoboxingStateCreation` в выборе числа карт для обмена (`mutableIntStateOf`). Остались detekt/Kotlin-анализ, проверка manifest/permissions и accessibility checks Compose; предупреждения lint-отчётов требуют постепенной очистки.

При отключённой анимации показывать статичный skeleton/индикатор; не запускать декоративное движение в невидимых composable. Файлы: `ui/components/Skeletons.kt`, `ui/components/UiKit.kt`.
- [ ] **Сократить постоянную стоимость shimmer и декоративных циклов.** Основные экраны skeleton-ов (альбом карточек, каталог, главная лента, тайтл, список, рейтинг, профиль) используют один общий shimmer-переход вместо отдельного бесконечного transition на каждый placeholder; Reduce motion оставляет статичный вариант. Общая lifecycle-проверка теперь останавливает shimmer, вращающийся halo `LoadingBox` и пульс `EmptyState` при `ON_STOP` (включая скрытую destination/фон) и возобновляет при `ON_START`. Осталось измерить нагрузку на слабом физическом устройстве и проверить остальные циклы.
- [ ] **Завершить состояния обратной связи интеракций.** Выбранная карта в кузнице меняет поверхность за 160 мс и мгновенно при системном Reduce Motion; на Compact Phone API 37 это вручную проверено с `animator_duration_scale=0`. Имя карты в строке кузницы теперь допускает две строки: при font scale 1.3 на Compact Phone API 37 пара «персонаж · тайтл» читается без обрезания первой строки. Появление результата и изменение размера панели кузницы мгновенные при системном Reduce Motion. Магазин, наборы и обмены показывают текст этапа операции. Нижняя навигация мгновенно переключает визуальное состояние при системном отключении анимации и сохраняет пружинный отклик при обычных настройках; переход «Лента → Каталог» вручную проверен на Compact Phone при animator/transition/window animation scale = 0. Для ежедневного бонуса, отдельных и массовых наград задания и прокрутки колеса флаги `actionBusy` и `spinning` сбрасываются через `finally`, в том числе при отмене coroutine. Ещё нужно пройти фильтры, закладки/скачивание, кнопки наград и snackbar во всём приложении. Использовать короткие переходы, избегать анимации layout-размеров для длинных списков.
- [ ] **Проверить анимацию переходов между экранами и восстановления состояния.** Для обычных экранов добавлен короткий fade-through при push/pop; системный запрет анимаций даёт мгновенный переход. Reader исключён из enter/exit переходов, чтобы не задерживать чтение и пагинацию. Нижние вкладки используют `saveState`/`restoreState`; вложенные вкладки карточек теперь сохраняют поисковые запросы, фильтры и сохранённую прокрутку через `SaveableStateProvider`; ещё вручную проверить scroll position/фильтры после возврата и отсутствие jank на компактном устройстве.
- [x] **Не сбрасывать вложенную страницу карточек при изменении системного масштаба.** `GamesScreen` сохраняет страницу хаба, а `CardsScreen` — активную вкладку и режим кузницы через `rememberSaveable`; переход на «Магазин» сохраняется после изменения font scale с 1.0 на 1.3 и возврата на 1.0 на Compact Phone API 37.
- [ ] **Сделать эффекты игрового раздела информативными и сдержанными.** В магазине выдача перед новым запуском очищается, повторный дроп снова запускает reveal, несколько одинаковых карт в паке имеют уникальные ключи списка, а появление/исчезновение награды учитывают Reduce Motion. Элемент выдачи теперь остаётся в lazy-сетке с постоянным ключом во время exit, поэтому `AnimatedVisibility` может завершить fade-out вместо мгновенного удаления родителем. Подпись активной случайной покупки совпадает с сайтом («Крутим…»). В «Рецепте бодрости» вспышка теперь привязана к реально собранным клеткам, а не к декоративному фиксированному столбцу. Декоративные лампы колеса теперь останавливаются при отключённых системных анимациях и пока destination не в состоянии STARTED; секундное обновление таймера обратного отсчёта тоже приостанавливается при скрытом экране и сразу синхронизируется при возврате; данные колеса и доступность прокрутки перезагружаются при возобновлении экрана; ещё измерить стоимость циклов и проверить прогресс заданий, сворачивание приложения во время запроса и другие игровые экраны.
- [ ] **Задать критерии производительности motion.** На реальных бюджетных устройствах измерить jank/кадры для ленты с изображениями, shimmer-сетки каталога, скролла читалки и вращения колеса; устранять лишние recomposition и дорогие blur/shadow только по измерениям.
