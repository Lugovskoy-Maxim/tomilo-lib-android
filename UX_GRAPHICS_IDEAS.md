# Идеи для графики и визуального UX

Цель — сделать интерфейс TOMILO LIB более узнаваемым и эмоциональным, не ухудшая скорость работы и читаемость. Визуальная база: тёмные поверхности, коралловый акцент, аккуратная манга-эстетика без перегруженных иллюстраций.

## Первый приоритет

### Иллюстрации для пустых состояний

Подготовить единый набор из 4–6 небольших иллюстраций в одном стиле:

- «Полка пуста» — стопка книг или закладка.
- «История пуста» — открытая книга и след от перелистывания.
- «Нет офлайн-глав» — книга с облаком и стрелкой загрузки.
- «Ничего не найдено» — лупа над панелью манги.
- «Нет уведомлений» — колокольчик или письмо.
- «Ошибка загрузки» — спокойная иллюстрация с кнопкой повторной попытки.

Иллюстрации должны занимать около 72–120 dp, иметь прозрачный фон и использовать коралловый, приглушённый белый и графитовые оттенки. Они заменяют абстрактные системные иконки там, где пользователь пока не получил контент.

### Единые иконки быстрых действий

Заменить стандартные Material-иконки на небольшой фирменный набор для главного экрана:

- Новые главы.
- Задания.
- Игры.
- Офлайн.
- Друзья.

Стиль: контурные иконки с одной акцентной заливкой, хорошо читаемые в размере 20–24 dp. Важно не смешивать разные стили иллюстраций и иконок.

### Заглушки обложек

Для тайтлов без постера использовать не однотонный фон, а набор ненавязчивых абстрактных паттернов:

- динамичные диагонали — экшен;
- точки и мягкие градиенты — романтика;
- геометрия и контраст — фантастика;
- более нейтральная композиция — неизвестный жанр.

Паттерн выбирается детерминированно по ID тайтла, чтобы его обложка не менялась между открытиями приложения.

## Второй приоритет

### Прогресс чтения на обложках

Показывать прогресс не только текстом:

- тонкая коралловая полоса внизу обложки;
- либо компактная дуга вокруг кнопки «Продолжить»;
- процент или номер последней главы — только при наличии места.

Прогресс должен быть вспомогательным: название тайтла и действия важнее.

### Графика наград и достижений

Для заданий, колеса и игровых разделов добавить коллекционные визуальные элементы:

- медали для достижений;
- печати/эмблемы для серий заданий;
- небольшие иконки валюты и опыта;
- карточки награды с редкостью: обычная, редкая, эпическая.

Это усилит ощущение прогресса и сделает игровые сценарии понятнее без длинных описаний.

### Косметика профиля

Добавить графические элементы, которые отражают статус пользователя:

- рамки аватара;
- фон профиля;
- премиум-акценты;
- значки за достижения и уровень.

Пользовательские фотографии и имя должны оставаться главным визуальным фокусом, поэтому декор — только по краю и с ограниченной яркостью.

## Третий приоритет

### Слабые фоновые текстуры

В hero-блоках и крупных разделах можно добавить почти незаметные текстуры:

- полутоновые точки;
- бумажное зерно;
- мягкая радиальная подсветка коралловым;
- редкие линии «страницы манги».

Контраст текстур должен быть низким: они не должны конкурировать с текстом, постерами или кнопками.

### Загрузки и переходы

Заменить нейтральную загрузку на фирменную микромоцию:

- перелистывание страницы;
- shimmer, проходящий по каркасу карточки;
- лёгкое появление обложек и списков.

Длительность анимаций — короткая; обязательна поддержка системного ограничения анимаций.

### Онбординг и системные разрешения

Для уведомлений, офлайн-скачиваний и входа использовать короткие иллюстрированные объяснения:

- что пользователь получит;
- какое действие требуется;
- как вернуться к настройке позже.

Не использовать полноэкранный онбординг без явной ценности: контент должен быть доступен сразу.

## Правила внедрения

- Предпочитать векторные ресурсы и небольшие WebP; не использовать тяжёлые PNG без необходимости.
- Соблюдать один визуальный язык: толщина линий, скругления, палитра и уровень детализации должны совпадать.
- Проверять контраст на тёмной теме и на маленьких экранах.
- Не передавать важный смысл только цветом или изображением — всегда оставлять текстовую подпись и `contentDescription`.
- Начинать с пустых состояний и быстрых действий: это даст наибольший эффект при минимальном риске для UX.
