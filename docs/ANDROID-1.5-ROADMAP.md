# Android 1.5: рабочий план

Цель: подготовить стабильное обновление приложения с быстрой загрузкой данных и обложек, сезонным оформлением, рабочими игровыми сценариями и cultivation-прогрессом профиля.

Этот список остаётся открытым, пока не пройдены проверки релизных APK/AAB и ключевые сценарии на устройстве. Компиляция подтверждает исходники, но не подтверждает работу API, оплат, кеша или игры на устройстве.

|---|---|---|---|

| Популярное | `GET /titles/popular` | Production check 2026-10-24: `public, max-age=120, stale-while-revalidate=600` и ETag. Для adult=false Android снимает JWT. | Главная; разрешённый HTTP cache. |
| Случайная подборка | `GET /titles/random` | Production check 2026-10-20: `public, max-age=180, stale-while-revalidate=300` и ETag. Android ограничивает каждый вызов общего media-клиента 8 секундами, включая чтение тела изображения. Страница читалки может пройти до трёх попыток, а WebtoonTiles дополнительно ограничивает source chain 24 секундами. Обложка карточки переключает источник после 10 секунд ожидания. Предел media call проверяется локальным медленным HTTP round-trip, а WebtoonTiles — unit-тестами; фактическое время загрузки и декодирования WebP/AVIF/JPEG ещё требуется измерить на устройстве и медленной сети.

24.10.2026 исправлен разрыв в таймаутах читалки: обычные изображения Coil раньше наследовали общий 60-секундный call timeout, а ограничение WebtoonTiles применялось не к каждой обычной странице. Media-клиент теперь ограничивает каждый вызов, включая чтение тела, восемью секундами; три попытки страницы занимают до 24 секунд. Таймаут внутри interceptor не сработал в HTTP round-trip тесте, поэтому лимит задаётся на клиенте до запуска запроса.

24.10.2026 исправлен retry читалки: cache-buster query-параметр менял подписанный S3 URL и мог приводить к отказу подписи. Повторный Coil-запрос теперь отключает Coil disk cache и передаёт OkHttp `Cache-Control: no-cache, no-store`, сохраняя URL и подпись. Unit-тест фиксирует неизменность подписанной ссылки на всех попытках; реальный retry подписанной страницы на устройстве ещё не проверен.

24.10.2026 анонимные production GET-запросы подтвердили текущие TTL и conditional ETag: обновления `200` за 0.711 с и `304` за 0.047 с; популярное `200` за 0.135 с, затем после смены ETag ответило `304` за 0.039 с; лидерборд `200` за 0.151 с и `304` за 0.262 с. Это замеры с компьютера, не Android и не CDN edge. Они подтверждают серверные заголовки и revalidation, но не Android cache hit/miss, account-switch isolation или время первого отображения.

24.10.2026 repeat production check: latest-updates returned HTTP 200, 16,436 bytes, `public, max-age=60, stale-while-revalidate=300` and ETag in 594 ms; conditional revalidation returned 304 without a body in 62 ms. Android-shaped leaderboard (`category=level&period=all&limit=50&page=1`) returned HTTP 200, 40,362 bytes and the same cache policy in 83 ms total (64 ms TTFB). These are single computer-side samples, not Android cache-hit or first-render timings.

The first latest-updates page also included cover key `titles/6ac6c1f38fdcd24936185d02/cover./api/wamanga/cover-proxy`. CDN HEAD returned 200, 49,954 bytes, `X-Tomilo-Cache: HIT` and public one-month caching; a range response had a RIFF/WEBP signature. Its `Content-Type` was malformed (`image//api/wamanga/cover-proxy`), so Coil decoding on-device and the source metadata still need verification. `MediaUrl` already keeps this CDN URL first and has S3 fallback; a regression test now covers that route. Play and RuStore suites passed 169/169 tests after the regression test.

Лента больше не запускает повторную загрузку на каждый `ON_RESUME`: после успешной или неуспешной попытки выдерживается 60-секундное окно; ручной pull-to-refresh и переход offline→online остаются немедленными. SDK РСЯ теперь инициализируется при первом запросе рекламы с экрана каталога/читалки, а не при старте `Application`; согласие применяется до и после завершения общей инициализации. На эмуляторе с недоступным DNS ранее регистрировался ANR при создании сервиса AppMetrica, похожие следы были и до этой правки. `dumpsys activity lastanr` текущего запуска сообщил, что после старта AVD ANR не было. Обе flavor прошли по 168 unit-тестов, lint и debug-сборки; холодный старт с актуальным APK всё ещё нужно проверить отдельно.

23.10.2026 главная применяет ответы обновлений и популярного сразу по их готовности; случайная карусель загружается независимо и больше не удерживает основные секции. Обе debug flavor прошли unit-тесты, lint и сборку после этой правки. Влияние на время до первого отображения нужно замерить на устройстве; сравнение запросов и cache hit/miss остаётся открытым.

23.10.2026 добавлена debug-only диагностика источника ответов API и обложек без URL и query. На эмуляторе обе flavor после conditional revalidation при первом запросе получили `hit` для `/titles/latest-updates`, `/titles/popular` и `/titles/random` после force-stop и повторного запуска; обложки в повторном запуске пришли из Coil `DISK`. Это время OkHttp-вызова, включая чтение JSON, не замер первого отображения.
