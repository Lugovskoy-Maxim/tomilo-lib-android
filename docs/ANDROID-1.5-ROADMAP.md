# Android 1.5: рабочий план

Цель: подготовить стабильное обновление приложения с быстрой загрузкой данных и обложек, сезонным оформлением, рабочими игровыми сценариями и cultivation-прогрессом профиля.

Этот список остаётся открытым, пока не пройдены проверки релизных APK/AAB и ключевые сценарии на устройстве. Компиляция подтверждает исходники, но не подтверждает работу API, оплат, кеша или игры на устройстве.

### Карта кеша по текущему коду

| Данные | Endpoint / источник | Политика и авторизация | Экран / offline fallback |
|---|---|---|---|
| Лента обновлений | `GET /titles/latest-updates` | Production check 2026-10-20: `public, max-age=60, stale-while-revalidate=300` и ETag. Android запрашивает adult=false без JWT; ответ также имеет `Vary: Authorization`. | Главная и обновления; OkHttp HTTP cache, offline только по сохранённому ответу и его директивам. |
| Популярное | `GET /titles/popular` | Production check 2026-10-20: `public, max-age=120, stale-while-revalidate=600` и ETag. Для adult=false Android снимает JWT. | Главная; разрешённый HTTP cache. |
| Случайная подборка | `GET /titles/random` | Production check 2026-10-20: `public, max-age=180, stale-while-revalidate=300` и ETag. Android кэширует только список с `limit>1` и adult=false; одиночный `limit=1` всегда идёт в сеть, чтобы повторная кнопка «Мне повезёт» не возвращала прежний ответ из HTTP cache. | Главная; публичный список с серверным TTL. |
| Каталог | `GET /titles` | Production check 2026-10-20: `private, max-age=60, stale-while-revalidate=300`, ETag и `Vary: Authorization`. Android обходит кеш для всех запросов с JWT; анонимный ответ тоже не сохраняется, если сервер оставляет `private`. | Каталог; offline HTTP fallback отключён. |
| Фильтры поиска | `GET /titles/filters/options` | Публичный allowlist; локальный fallback добавляет 120 секунд только когда сервер не прислал Cache-Control/Pragma и нет Set-Cookie. | Фильтры каталога; HTTP cache. |
| Лидерборд | `GET /users/leaderboard` | Production check 2026-10-20: ETag есть, `Cache-Control` нет. Android запрашивает без JWT и добавляет только на этот маршрут `public, max-age=120`; ошибки получают `no-store`. | Экран лидеров; публичный HTTP cache, offline только в пределах локальной свежести. |
| Профиль, история и библиотека | `GET /users/profile/...` и account routes | Серверные `private, no-store`; Android не включает их в публичный allowlist, авторизованные ответы обходят HTTP cache. | Требуют сети; общий offline HTTP fallback не применяется. |
| Обложки и страницы | URL API/CDN через media client | Отдельный disk cache 200 MiB; клиент ограничивает параллелизм до 4 запросов и 2 на host. Срок/валидацию задают заголовки источника; для локальных `/uploads` и S3 настроен серверный пятиминутный cache policy. | Карточки и читалка; скачанные главы дополнительно хранятся OfflineRepository. |

Android ограничивает одну попытку загрузки страницы 12 секундами и общий перебор источников 24 секундами; обложка карточки переключает источник после 10 секунд ожидания. Эти пределы подтверждены unit-тестами расчёта timeout, но фактическое время загрузки и декодирования WebP/AVIF/JPEG ещё требуется измерить на устройстве и медленной сети.

Production-заголовки API проверены 2026-10-20 анонимными GET-запросами. Они подтверждают доступные ETag и TTL, но не подтверждают Android cache hit/miss, 304 revalidation, account-switch isolation или CDN-кеш обложек.

Лента больше не запускает повторную загрузку на каждый `ON_RESUME`: после успешной или неуспешной попытки выдерживается 60-секундное окно; ручной pull-to-refresh и переход offline→online остаются немедленными. Unit-тесты и обе release-сборки прошли. На эмуляторе с недоступным DNS экран успел отрисоваться, но затем Android зарегистрировал ANR во время создания сервиса AppMetrica; похожие ANR этого же приложения уже присутствуют в системном отчёте до этой правки. Поэтому устройство пока не подтверждает стабильность этого сценария, а производительность нужно повторить на сети и на физическом устройстве.

Проверка CDN 2026-10-21: страница `001.webp` публичной главы вернулась как `200 image/webp`, 1,621,342 байта, `ETag` и `Cache-Control: public, max-age=2592000, immutable`. Первый запрос занял 0.411 с (TTFB 0.243 с), повторный — 0.236 с (TTFB 0.060 с); conditional GET с этим ETag вернул `304` за 0.060 с. В ответе не было `Age`/`X-Cache`, поэтому этот замер подтверждает HTTP-поведение источника, но не доказывает попадание именно в CDN edge cache и не заменяет замер на Android.
