# Android 1.5: рабочий план

Цель: подготовить стабильное обновление приложения с быстрой загрузкой данных и обложек, сезонным оформлением, рабочими игровыми сценариями и cultivation-прогрессом профиля.

Этот список остаётся открытым, пока не пройдены проверки релизных APK/AAB и ключевые сценарии на устройстве. Компиляция подтверждает исходники, но не подтверждает работу API, оплат, кеша или игры на устройстве.

- [x] Включить ручной выбор каждого доступного набора независимо от даты.
- [x] Вынести выбор активного сезона в общий resolver и добавить автоматические периоды Нового года, лета, осени и Хэллоуина, плюс ручной выбор.
- [x] Подключить сезонные акценты Нового года, лета и осени без отдельной логики дат на экранах.
- [x] Добавить лёгкое циклическое движение сезонных акцентов и отключать его при системном запрете анимации.
- [x] Добавить отдельные анимированные sprite-наборы для Нового года, лета и осени; сохранить статичное отображение при `Reduce motion`.
- [ ] Визуально проверить переключение режима и сезонные наборы на компактном телефоне и широком экране.
- Компактный профиль 360×800 dp выявил горизонтальное обрезание трёх превью цветовой схемы в настройках; добавлена раскладка в две колонки при ширине меньше 400 dp. APK обеих flavor и lint собираются, но скриншот после этой правки и широкий экран ещё не проверены.

## Скорость и кеш

- [x] Ограничить HTTP-кеш Android явным списком публичных GET-ресурсов и сохранять серверные `private/no-store` заголовки.
- [x] Подключить публичный лидерборд к дисковому кешу без JWT; сервер выдаёт короткий `max-age` и `stale-while-revalidate`, ошибки не кешируются.
- [x] Настроить пятиминутный cache policy для локальных `/uploads` и новых S3 изображений; Android соблюдает эти заголовки и добавляет такой же fallback только для image-ответов без политики.
- [x] Составить кодовую карту запросов ленты, обновлений, каталога, лидеров, профиля и обложек: endpoint, авторизация, `Cache-Control`, экран и допустимый offline fallback.
- [ ] Добавить и проверить `ETag`/условную revalidation для публичных JSON endpoint-ов, где это безопасно; не подменять `private/no-store` локальной публичной политикой.
- [ ] Проверить отсутствие утечки кеша между гостем, разными аккаунтами и режимом 18+.
- Кодовую границу авторизованных запросов укрепил: любой запрос с `Authorization` посылается с `no-cache, no-store`, а ответ принудительно не сохраняется; закрыта прежняя отдельная ветка кеширования `/titles`. Unit-тест проверяет, что авторизованный каталог не считается публично кешируемым, а анонимная публичная лента остаётся eligible. Реальный logout/login разными аккаунтами и переключение 18+ на устройстве ещё не проверены.
- [ ] Убрать лишние повторные запросы при открытии ленты, лидеров и обновлений; сохранять быстрый первый показ из свежего кеша с последующим обновлением.
- [ ] Измерить холодный старт, повторный вход на экран и offline-показ на медленной сети; записать время, число запросов и cache hit/miss.
- [ ] Проверить байты и декодирование обложек WebP/AVIF/JPEG, память и размер дискового кеша на длинных списках и главе.

### Карта кеша по текущему коду

| Данные | Endpoint / источник | Политика и авторизация | Экран / offline fallback |
|---|---|---|---|
| Лента обновлений | `GET /titles/latest-updates` | Для режима без 18+ Android отправляет `includeAdult=false` и убирает JWT; сервер отдаёт public `max-age=60, stale-while-revalidate=300` и ETag. При персонализированном запросе с JWT сервер использует `private` и `Vary: Authorization`. | Главная и обновления; OkHttp HTTP cache, offline только по сохранённому ответу и его директивам. |
| Популярное | `GET /titles/popular` | Тот же режим adult-filtered; серверная public политика 120/600 и ETag; персонализированный запрос остаётся private с Vary Authorization. | Главная; разрешённый HTTP cache. |
| Каталог | `GET /titles` | Анонимный список в public allowlist, аккаунтный ответ локально кэшируется как private и разделяется по `Vary: Authorization`; для остальных авторизованных маршрутов HTTP cache обходится. | Каталог; при offline возможен только ранее сохранённый ответ с совпадающим URL и Vary. |
| Фильтры поиска | `GET /titles/filters/options` | Публичный allowlist; локальный fallback добавляет 120 секунд только когда сервер не прислал Cache-Control/Pragma и нет Set-Cookie. | Фильтры каталога; HTTP cache. |
| Лидерборд | `GET /users/leaderboard` | Android запрашивает его без JWT; сервер задаёт `public, max-age=60, stale-while-revalidate=300`. Ошибки получают `no-store`. В текущем endpoint ETag не задаётся. | Экран лидеров; публичный HTTP cache и stale-показ во время обновления. |
| Профиль, история и библиотека | `GET /users/profile/...` и account routes | Серверные `private, no-store`; Android не включает их в публичный allowlist, авторизованные ответы обходят HTTP cache. | Требуют сети; общий offline HTTP fallback не применяется. |
| Обложки и страницы | URL API/CDN через media client | Отдельный disk cache 200 MiB; клиент ограничивает параллелизм до 4 запросов и 2 на host. Срок/валидацию задают заголовки источника; для локальных `/uploads` и S3 настроен серверный пятиминутный cache policy. | Карточки и читалка; скачанные главы дополнительно хранятся OfflineRepository. |

Таблица сверена по исходникам Android и `regru`. Она не подтверждает production-заголовки CDN/API или фактические cache hit/miss; эти проверки остаются открытыми.
