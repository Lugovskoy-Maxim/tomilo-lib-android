# Прямой вход через VK ID и Яндекс

Экран входа запускает `NativeOAuthActivity`, которая использует VK ID SDK 2.7.3
и Яндекс LoginSDK 3.1.3. SDK выбирает приложение провайдера или свой браузерный
сценарий. Страницы `tomilo-lib.ru/auth/*` в этом потоке не участвуют.
API Tomilo проверяет результат у провайдера и выдаёт собственную сессию,
сохраняя общие профиль, полку и историю.

## Настройки сборки

Скопировать `secrets.properties.example` в `secrets.properties` (игнорируется Git).
Значения также можно задать через переменные окружения или Gradle properties:

```properties
VKID_CLIENT_ID=54445438
VKID_CLIENT_SECRET=<защищённый ключ приложения VK ID>
YANDEX_AUTH_CLIENT_ID=ffd24e1c16544069bc7a1e8c66316f37
```

Это настройки OAuth-приложений провайдеров. Ключ RuStore API сюда не подходит.
Не коммитить `secrets.properties`. VK SDK требует client_secret в метаданных
Android-приложения по своей схеме интеграции; секрет API публикации RuStore
никогда не включается в APK. Не использовать серверные секреты других сервисов.

Без `VKID_CLIENT_SECRET` кнопка VK использует прежний поток входа через браузер внутри приложения.
Email и Яндекс доступны независимо от VK. Существующие Client ID перенесены из
предыдущего потока; наличие зарегистрированных Android-платформ пока не проверено.

## Кабинеты провайдеров

Для каждого выпуска добавить соответствующие пакеты и сертификаты:

| Канал | Android package |
| --- | --- |
| RuStore | `ru.tomilo.lib.mobile` |
| Google Play | `ru.tomilolib.mobile` |

- Яндекс OAuth: Android-платформа, package name, SHA-256 сертификата подписи,
  разрешения на профиль и email. Для Google Play использовать сертификат
  **App Signing**, которым магазин подписывает установленные приложения.
- VK ID: Android-платформа, package name, отпечаток сертификата, защищённый ключ
  того же приложения, разрешение `email`. Callback SDK:
  `vk54445438://vk.ru/blank.html` (при смене ID меняется схема).
- Для debug добавить отпечаток debug-сертификата отдельно. Получить отпечатки:
  `./gradlew :app:signingReport`.

В API `POST /auth/vk-id` должен быть настроен тот же `VK_ID_CLIENT_ID`, что в
Android-сборке. Запрос передаёт `code`, `code_verifier`, `device_id`, `state`,
`redirect_uri`. Сервер должен использовать переданный native redirect при обмене
кода, а не подставлять адрес сайта. В текущем локальном исходнике backend это
поддерживается; состояние production не проверено. При переходе на отдельный
Android Client ID потребуется согласовать его с backend до выпуска.

Яндекс: SDK возвращает access token, приложение отправляет его в существующий
`POST /auth/yandex-token`. Токен провайдера не сохраняется приложением.
VK: приложение создаёт новый verifier/challenge/state для каждой попытки;
SDK проверяет state, а одноразовый код обменивается на сервере.

## Проверка перед выпуском

1. Настроить оба кабинета и сборку, запустить unit tests и сборку APK.
2. Проверить успешный вход с приложением провайдера и без него.
3. Проверить отмену, повторный вход, отсутствие сети, поворот экрана,
   возврат после завершения процесса. Прерванный VK-поток предлагает начать заново.
4. Убедиться, что профиль/полка загрузились и сессия сохранилась после перезапуска.

Полный вход требует реального аккаунта и настроенных кабинетов; успешная сборка
сама по себе его не подтверждает.

Источники: [VK ID SDK](https://github.com/VKCOM/vkid-android-sdk),
[Яндекс LoginSDK](https://yandex.ru/dev/id/doc/ru/mobileauthsdk/android/3.1.3/sdk-android-use).
