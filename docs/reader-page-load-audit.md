# Аудит читалки: чёрная страница и недогруз после нарезки

Дата: 2026-09-29. Код: `ReaderScreen.kt` (`WebtoonReader`, `TiledWebtoonPage`, `WebtoonTileImage`, `ReaderPage`), `WebtoonTiles.kt`, `PageImages.kt`.

Нарезка включается только в режиме вебтуна и только если у страницы есть ненулевые `pageDimensions`. Иначе страница идёт через Coil (`ReaderPage`). Постраничный режим (`PagerReader`) не нарезает.

Математика швов в `WebtoonTilesTest` сходится: плитки стыкуются без зазора. Чёрный экран даёт не формула `mapTileToSource`, а то, как плитка рисуется и как декодер отдаёт bitmap.

## 1. После нарезки первый экран чёрный, спиннера не видно

`WebtoonTiles.split` режет исходник кусками до 4096 px по высоте (`MAX_TILE_SOURCE_HEIGHT`). `WebtoonTileImage` занимает бокс с `aspectRatio(tile.width / tile.height)` и фоном `Color.Black`.

На ширине телефона плитка 4096 px — это несколько экранов. Спиннер и текст «Не загрузился фрагмент» стоят по центру бокса (`contentAlignment = Alignment.Center`), а не в видимой части. Пока декод не закончился, пользователь смотрит на верх плитки: сплошной чёрный, без индикатора.

То же при ошибке: сообщение оказывается на 2–3 экрана ниже, сверху снова чёрное.

Что сделать:

- Резать плитку по высоте примерно в один экран (от ширины экрана), а не по 4096 px исходника.
- Индикатор и ошибку прижимать к верху плитки, внутри первого экрана.
- Пока bitmap нет, не оставлять многоэкранный чёрный резерв.

## 2. Нижние плитки остаются чёрными без загрузки

У плитки с `tile.index != 0` старт такой: `active = false`, `bitmap = null`, `loading = false`. Спиннер рисуется только при `loading && bitmap == null`. До колбэка `onGloballyPositioned` это чёрный прямоугольник без индикатора.

Дальше `active` выключается, если плитка вышла из окна `-0.5…+1.5` экрана. Выключение отменяет текущий `LaunchedEffect`, через 900 мс обнуляет bitmap. Повторный декод начнётся только если `onGloballyPositioned` снова поставит `active = true`.

Если колбэк больше не приходит (координаты не изменились после очистки bitmap, сбой первого layout), плитка так и остаётся чёрной: не грузится, ошибки нет, кнопки «Повторить» нет.

У верхней плитки (`eager = true`) декод не отменяют, пока нет bitmap или ошибки. После успешной загрузки её тоже можно погасить тем же условием и больше не включить.

Что сделать:

- Не гасить bitmap и не отменять декод из-за короткого выпадения из окна. Снимать bitmap только когда страница ушла из композиции.
- Видимость брать из `LazyListState` / пересечения с viewport на каждом кадре скролла, а не из одноразового `onGloballyPositioned`.
- Если плитка в композиции и пересекает экран, а bitmap пустой — всегда показывать индикатор и запускать декод, даже если прошлый `active` залип в `false`.

## 3. Офлайн-глава сначала рисуется целиком, потом схлопывается в чёрные плитки

В `loadChapter` для локальных страниц порядок такой: `pages = localSources`, `loading = false`, и только потом `pageDimensions = measureLocalSources(...)`.

Пока размеров нет, `WebtoonReader` выбирает `ReaderPage` (Coil). Когда размеры приезжают, та же страница переключается на `TiledWebtoonPage`: Coil отменяется, бокс становится чёрным, заново качается/мерится файл и режется. Это и есть чёрный кадр «после разбивки» на скачанной главе.

Что сделать:

- Для вебтуна не показывать страницу, пока не готовы локальные размеры, либо не переключать уже нарисованный Coil-кадр на плитки.
- Если плитка локального файла не декодируется, оставить файл в Coil (`file:`), а не чёрный бокс.

## 4. Нет запасного пути, если нарезка не умеет формат

`BitmapRegionDecoder` (minSdk 26) нормально режет JPEG и часть PNG/WebP. AVIF он не режет: `newInstance` возвращает `null` либо `decodeRegion` падает. Страницы с расширением avif при этом попадают в нарезку, если `BitmapFactory` на API 31+ смог прочитать только bounds.

Плиточный путь не возвращается к `ReaderPage`. Coil на API 28+ как раз умеет AVIF/WebP через `ImageDecoder`. Сейчас ошибка декодера остаётся внутри огромной чёрной плитки.

`inSampleSize` включается, когда ширина файла больше 2048 (`MAX_DECODE_WIDTH`). У WebP региональный декод с `inSampleSize` 2/4 на части прошивок возвращает чёрный bitmap без исключения. `cropToRequested` проверяет только размер, не то, что пиксели не чёрные. Чёрный bitmap считается успехом.

Повтор не лечит: `sourceFile` при повторном вызове отдаёт уже скачанный `*.source`, если у файла ненулевые bounds. Битый или урезанный WebP с целым заголовком кэшируется навсегда. `retry` / «Повторить» только снова декодируют тот же файл.

Что сделать:

- Если `BitmapRegionDecoder` недоступен, регион пустой или bitmap почти чёрный — один раз передекодировать регион с `inSampleSize = 1`. Если снова плохо, рисовать страницу целиком через Coil/ImageDecoder с уже скачанного файла, без второго HTTP.
- Прямоугольник региона выравнивать по MCU (кратно 16, внутри кадра) и обрезать лишнее. Сейчас обрезается только ответ декодера, сам запрос не выровнен.
- При неудачном декоде удалять `webtoon_sources/*.source`. Повтор должен качать заново, а не читать тот же кэш.
- В `sourceFile` не глотать `CancellationException` (`catch (failure: Throwable)` сейчас крутит следующий CDN после отмены).

## 5. Если measure сорвался, нарезка всё равно идёт по размерам сервера

`TiledWebtoonPage` ждёт `measureSource`. При ошибке подставляет серверные `pageDimensions`:

`sourceDims = measured ?: dimensions.takeIf { it.isValid() }`

Комментарий рядом говорит, что нарезка по серверным размерам даёт кривые границы WebP. Отображаемый бокс тогда считается из заявленной плитки, а bitmap — из другого кадра. Узкая полоска исходника растягивается на высокий чёрный/мыльный блок.

Что сделать:

- Не резать страницу, если файл не измерился. Оставить `ReaderPage`.
- Серверные размеры использовать только как запасной aspect у плейсхолдера, не как сетку плиток.

## 6. Недогруз из-за того, что вся страница — один элемент списка

`WebtoonReader` кладёт все плитки одной страницы в один item `LazyColumn`. Длинная страница на 20–30 тысяч px собирается целиком.

У каждой такой страницы первая плитка `eager`: она сразу качает весь исходник в `cacheDir/webtoon_sources`, даже если страница ещё далеко. `LazyColumn` держит несколько item впереди. Несколько полных WebP качаются параллельно, видимая страница ждёт очередь. Отдельного лимита загрузок нет.

Кэш Coil и кэш `webtoon_sources` разные. Падение нарезки не подхватывает файл, который Coil уже скачал, и наоборот.

Плитки не сообщают статус в `handlePageState` / `failedPages`. Надпись «Не загрузилось страниц» и общий повтор главы плиток не касаются.

Что сделать:

- Ограничить одновременные скачивания исходников (1–2 на читалку). Eager только у страницы, которая уже на экране.
- Либо сделать плитки отдельными item `LazyColumn`, чтобы вне экрана они не создавались.
- После первой неудачи плиток переключать всю страницу на Coil и считать её в `failedPages`.
- Отдавать в Coil локальный путь из `webtoon_sources`, не качать тот же URL вторым клиентом.

## 7. Скачанная глава без части файлов выглядит как оборванная, не как ошибка

`OfflineRepository.getLocalPages` отдаёт любые целые картинки и не сверяет их число с `pageCount`. Дыра в нумерации (`0001`, `0002`, `0004`) просто пропадает. Читатель видит скачок сюжета, а не чёрную страницу и не текст «файл повреждён».

Что сделать:

- Если файлов меньше, чем `pageCount`, писать в главе, что скачивание неполное, и не притворяться, что это вся глава.
- Битый файл между целыми не выкидывать молча: на его месте плитка с ошибкой и повтором, с тем же номером страницы.

## 8. Постраничный режим и Coil — отдельный чёрный фон

`PagerReader` и вебтун без размеров рисуют `ReaderPage` на `Color.Black`, пока нет `loaded`. Это нормальный плейсхолдер, не нарезка.

Coil ограничивает декод `1080×16384`. Очень длинная страница без `pageDimensions` может не собраться в один bitmap и остаться на спиннере или на ошибке. Автоповтор есть (`PageRetryPolicy`, до 3 попыток) и сбрасывает дисковый кэш Coil. Валидный, но визуально чёрный JPEG/WebP (успешный декод, размер ≥ 8 px) считается загруженным и не ретраится.

Что сделать:

- Страницу выше ~16K без рабочих `pageDimensions` не отдавать в один Coil-запрос: либо нарезка по файлу после `measureSource`, либо явная ошибка «страница слишком длинная», а не бесконечный спиннер.
- Чёрный успешный bitmap в Coil считать ошибкой так же, как в плитке.

## 9. Две загрузки одной читалки пишут состояние друг поверх друга

`loadChapter` каждый вызов делает `scope.launch` и нигде не отменяет прошлый запуск. Перед записью страниц нет сверки, что `id` всё ещё открытая глава.

`loading = true` ставится уже внутри корутины. До первого `suspend` (`readingPosition` / `isDownloaded`) повторный тап по другой главе в списке успевает запустить второй запуск. У Premium и в офлайне `goChapter` зовёт `loadChapter` сразу, без отсчёта. Оба запроса доходят до конца: поздний ответ старой главы подменяет `pages`, `pageDimensions`, `error` и `loading` у новой.

На экране чужие страницы, пустой список или ошибка не той главы. Пока список пустой, вебтун не рисуется — выглядит как неоткрывшаяся глава.

Что сделать:

- Держать один `Job` загрузки и отменять его в начале новой.
- После каждого `suspend` выходить, если глава уже другая.
- `loading = true` ставить до `launch`, чтобы второй переход видел, что первая загрузка идёт.

## 10. Позиция чтения восстанавливается до нарезки

Офлайн ставит `pages` и `loading = false`, и только потом `pageDimensions = measureLocalSources(...)`. Эффект скролла зависит от `loading` и `pages.size`, не от размеров.

Он делает `scrollToItem` по ещё целой Coil-странице. Когда размеры приезжают, тот же item становится колонкой плиток другой высоты. Сохранённый offset попадает в середину высокой чёрной плитки или ниже видимого кадра. Это продолжение п. 3: кроме чёрного кадра сбивается место, на котором остановились.

Что сделать:

- Не восстанавливать скролл, пока для вебтуна не готовы локальные размеры (или пока решено оставить Coil).
- После смены Coil → плитки не переиспользовать старый `scrollOffset`.

## 11. Битый WebP и любой AVIF считаются целой страницей, докачка их не чинит

`ImageIntegrity.decodeLooksUsable` для WebP возвращает true, даже если `BitmapFactory` не прочитал bounds. `canDecodeBounds` для AVIF возвращает true по заголовку `ftyp`, без декода.

Такой файл проходит в `getLocalPages`. Плитка или Coil рисуют чёрный кадр / ошибку, а файл остаётся «валидным».

Повторное скачивание дыру не закрывает. `downloadChapter` при любом непустом `getLocalPages` и живой строке Room сразу отвечает «Уже скачано» и не смотрит `pageCount`. Недостающие и битые номера так и не докачиваются. Это механизм, из-за которого п. 7 не лечится само.

Что сделать:

- Считать WebP целым только при bounds не меньше 8×8. AVIF проверять декодером, не строкой бренда.
- «Уже скачано» только если целых файлов столько же, сколько `pageCount`, без дыр в нумерации.
- Иначе докачать недостающие номера, не списывая кредит повторно.

## 12. Докачка с другим расширением добавляет лишнюю страницу

Имя файла `%04d.ext` берётся из текущего URL. Если раньше лежал `0003.webp`, а новый URL с `.jpg`, старый файл не удаляется: проверка `isValidFile` смотрит только новое имя.

`getLocalPages` сортирует по имени и отдаёт оба. В главе появляется лишняя страница, номера съезжают, дальше по списку читается не тот кадр.

Что сделать:

- Перед записью страницы удалять в папке главы все `0003.*`, не только точное имя с новым расширением.

## 13. Обрезка кэша удаляет исходник, который ещё режется

`trimCache` после скачивания удаляет чужие `webtoon_sources/*.source` по времени, как только каталог больше 600 МБ. Декод другой страницы открывает файл по пути и не держит его в «занятых».

Удаление посередине `BitmapRegionDecoder.newInstance` даёт пустой регион или ошибку. Если на диске остался обрезанный файл с живым заголовком, `isImage` больше не качает его заново (п. 4).

Что сделать:

- Не удалять файл, пока его декодирует хотя бы одна плитка.
- После неудачного `decodeRegion` удалять `*.source`, как уже сказано в п. 4.

## 14. Все плитки страницы держат bitmap сразу

`WebtoonReader` кладёт все плитки страницы в один item. Каждая плитка хранит ARGB-bitmap на всю свою высоту (до 4096 px исходника, минус `inSampleSize` только по ширине). Соседние item `LazyColumn` тоже собраны.

Когда плитка выходит из окна, ссылка обнуляется (`bitmap = null`) без `recycle()`. На длинной главе процесс упирается в память и умирает. После возврата читалка снова открывается с чёрного первого экрана.

Что сделать:

- Резать плитку по высоте экрана (п. 1), чтобы bitmap был одним экраном.
- `recycle()` в момент сброса и при уходе страницы из композиции.
- Не создавать плитки далеко за экраном (п. 6).

## 15. В постраничном режиме зум не получает жест

`PagerReader` рисует поверх `HorizontalPager` ряд из трёх `clickable` на весь экран. Жест забирает оверлей. `transformable` у `ReaderPage` под ним не видит пальцы: зум и сдвиг в постраничном режиме не работают. Тап по странице тоже не доходит, зоны листания живут только в оверлее.

К чёрной плитке это не относится. Страница при этом может так и остаться в стартовом масштабе, если жест ждали как способ рассмотреть кадр.

Что сделать:

- Зоны листания не должны перехватывать жест с двумя пальцами и жест панорамирования при масштабе больше 1.
- Либо вешать зум на тот же слой, что и зоны.

## Порядок правок

1. Мелкие плитки и индикатор в видимой зоне — убирает чёрный первый экран сразу после разбивки.
2. Не переключать офлайн-Coil на плитки посередине кадра и не восстанавливать скролл до стабильной высоты.
3. Запасной полный рендер и сброс битого `*.source`, если регион чёрный или формат не режется.
4. Лимит параллельных скачиваний и общий статус ошибки страницы.
5. Честная дырка в офлайн-главе: не считать битый WebP/AVIF целым и не отвечать «Уже скачано», пока файлов меньше `pageCount`.
6. Одна загрузка главы за раз, отмена предыдущей.
7. Перед докачкой страницы удалять старые файлы того же номера с другим расширением.
